## 24-1 Redis的持久化
Redis 里主要有 **RDB(内存快照)** 和 **AOF(追加日志)** 两种持久化方案

### RDB 
RDB的持久化策略可以设置为，如果在 60 秒内至少有 1 个 key 发生变化，就自动触发一次 RDB 快照保存的机制


### 两种规则的区别
| **特性**       | **RDB（内存快照）**                                          | **AOF（追加日志）**                                          |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **工作原理**   | 指定时间间隔内，将内存全量数据生成快照写入磁盘文件（如 `dump.rdb`）。 | 将接收到的每一条写命令（SET、DEL等）以日志形式追加到文件末尾（如 `appendonly.aof`）。 |
| **数据安全性** | **较差**。如果在两次快照之间宕机，会丢失上一次快照之后的所有数据。 | **较高**。根据刷盘策略，最多仅丢失 1 秒或当前这条指令的数据。 |
| **性能影响**   | **低**。主进程只需 `fork` 子进程去处理磁盘 I/O，不影响主进程的读写性能。 | **中/高**。频繁写磁盘，对磁盘 I/O 有一定压力（取决于刷盘策略）。 |
| **文件体积**   | **小**。采用二进制压缩存储，极其紧凑。                       | **大**。文本格式记录所有写指令，即便经过重写（AOF Rewrite）也通常比 RDB 大。 |
| **恢复速度**   | **极快**。直接解析二进制快照装载进内存，适合快速恢复大量数据。 | **较慢**。需要重新逐条执行文件中保存的写命令。 

### 两种规则在配置文件里的参考
```
# --- RDB 配置 ---
save 900 1            # 900 秒内至少 1 个修改，触发 RDB
save 300 10           # 300 秒内至少 10 个修改，触发 RDB
rdbcompression yes    # 开启压缩

# --- AOF 配置 ---
appendonly yes                       # 开启 AOF
appendfilename "appendonly.aof"      # 保存的文件名
appenddirname "appendonlydir"        # 相关文件的 文件夹名

# AOF 刷盘策略（三选一，推荐 everysec）
# appendfsync always                 # 每次写命令都刷盘（安全但极慢）
appendfsync everysec                 # 每秒异步刷盘一次（兼顾性能与安全，默认推荐）
# appendfsync no                     # 由操作系统决定什么时候刷盘（性能最高但最不安全）

# --- 混合持久化（Redis 4.0+ 默认开启）---
aof-use-rdb-preamble yes
```

### 操作
这里教程选择了 **AOF** 策略，在配置文件中找到 `appendonly no`，将其改为 `yes` ，开启状态  
appendfsync everysec 默认开启，不用管

## 24-3 js拼接当前日期并渲染
核心只有一个方法，直接贴出来应该能看懂，细节和 C# 有所不同
```
var setDeliveryDate = () => {
    // 创建时间对象
    var date = new Date()
    //获取当前年份
    var year = date.getFullYear()
    //获取当前月份 (注：js获取的月份是从0开始的，也就是0即为1月)
    var orgMonth = date.getMonth()
    var month = orgMonth + 1 < 10 ? "0" + (orgMonth + 1) : orgMonth + 1
    //获取当前日期 (注：与月份一样，都是从0开始)
    var orgDay = date.getDate()
    var day = orgDay + 1 < 10 ? "0" + (orgDay + 1) : orgDay + 1

    //返回适配 input date 标签的日期格式
    deliveryDate.value = `${year}-${month}-${day}`
}
```

关于获取对象，有更简洁的写法：
```
//获取 +1 天的 Date 对象
const tomorrow = new Date()
tomorrow.setDate(tomorrow.getDate() + 1)

//获取 日期 并补 "0"
const day = String(tomorrow.getDate()).padStart(2, '0')
```

其他数据如 **年、月** 同理  
这里的 `String(tomorrow.getDate())` 指的是把 `getDate` 获取的日期转换成 `string` 对象  
`padStart` 指的是检查字符串长度是否到达目标长度，假设 `getDate` 这里返回的是 **"9"**,`padStart` 发现目标长度没到 **2**，则在前面加上一个 **"0"**。(妈耶这个方法作用也太垂直了)
