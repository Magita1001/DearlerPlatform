### 这里讲一下 `事务` 的概念

**正式一点介绍**：  
事务（Transaction）是数据库和系统开发中的一个核心概念，指的是**一组作为单个不可分割的逻辑工作单元执行的操作**。

它的核心思想就是：**“要么全部成功，要么全部失败（回滚）”**。

**通俗一点就是**：比如添加信息到**主表**、**明细表**、**进度表** 的一组操作里，如果某一个环节 **寄了**，那么数据就会进入到一个只插入了一部分，剩下的宕机的尴尬场景，所以就需要把进行了的操作，全部**回滚重来**。

### 事务的四大核心特性（ACID 特性）

数据库事务必须满足经典的 **ACID** 原则：

| **特性**       | **全称**    | **解释**                                                     |
| -------------- | ----------- | ------------------------------------------------------------ |
| **A - 原子性** | Atomicity   | 事务是最小的不可分割单元。“要么全做，要么全不做”。           |
| **C - 一致性** | Consistency | 数据库在事务执行前后都处于合法一致的状态（如：转账前后两人的总金额保持不变）。 |
| **I - 隔离性** | Isolation   | 多个事务并发执行时，它们之间互不干扰、相互隔离（避免脏读、不可重复读等）。 |
| **D - 持久性** | Durability  | 事务一旦提交（Commit），它对数据库的修改就是永久性的，即使数据库崩溃关机也不会丢失。 |

**操作**：这里引入事务 `TransactionScope`，他需要 `using` 来配合使用

> using TransactionScope ts = new TransactionScope();

**重要**：在 C# 异步编程（``async/await``）中使用 `TransactionScope` 时，**必须加上** `TransactionScopeAsyncFlowOption.Enabled` **参数**，否则异步线程切换会导致事务上下文丢失而报错！

> using TransactionScope ts = new TransactionScope(TransactionScopeAsyncFlowOption.Enabled);

把 `AddOrder` 里的所有代码包裹在 `try-catch` 里，try的结尾补上 `ts.Complete();` ，事务就会**正式应用**所有数据，反之如果抛出异常，进入到 catch 里，就会执行 `ts.Dispose();`，回滚所有数据

据说使用 `TransactionScope` 的话，不写trycatch也行，他好像是离开代码块自动执行 `ts.Dispose`

**注**：事务只能操作**数据库服务**的数据，不能操作C#变量
