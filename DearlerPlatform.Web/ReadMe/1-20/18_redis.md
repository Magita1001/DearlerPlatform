## 18-4 Redis
### Redis 的五大基础数据结构：
Redis 中的数据结构都是围绕着 **Key-Value** 展开的(string)

1. **`string`（字符串）**
   - **是什么**：最基础的键值对（KV）。不仅能存文本，还能存数字、甚至是**图片**，最多可以保存 **512M** 的数据。
   - **通俗比喻**：贴了标签的抽屉盒，一个 key 对应一个值。
   - **常用场景**：缓存 JSON 字符串、保存用户 Token、验证码，或者用 `INCR` 指令做计数器（如点赞数）。

2. **`hash`（哈希）**
   - **是什么**：一个 Key 下面又包含了一个“字段-值”（Field-Value）的字典映射。
   - **通俗比喻**：一个文件夹（Key），里面放着一张表格（包含姓名、年龄、性别等字段）。
   - **常用场景**：**存储对象数据**。比如存一个用户信息，不用把整个 User 序列化成 JSON，可以直接修改里面的 `Age` 字段。

3. **`list`（列表）**
   - **是什么**：按插入顺序排序的双向链表，支持从左右两端压入/弹出元素。
   - **通俗比喻**：食堂排队取餐的队伍。
   - **常用场景**：简易消息队列、最新动态列表（如最新的 10 条新闻）。

4. **`set`（集合）**
   - **是什么**：无序且**元素绝对不重复**的集合，支持交集、并集、差集计算。
   - **通俗比喻**：一个抽奖箱（里面球的名字各不相同，摸出来是随机的）。
   - **常用场景**：抽奖（不重复中奖）、标签（Tag）、求共同好友（取两个 Set 的交集）。

5. **`zset`（sorted set / 有序集合）**
   - **是什么**：在 Set 的基础上，给每个元素关联了一个**分数（Score）**，Redis 会根据分数自动给元素排序。
   - **通俗比喻**：带着考试成绩的高考榜单。
   - **常用场景**：**各类排行榜**（游戏积分榜、微博热搜榜）、延迟任务调度。



### Redis 的 Key-Value 类型
在 Redis 中有一个黄金法则：**所有的 Key（键）在底层无一例外，统一都是“二进制安全的字符串（String）”**。

区别和复杂性完全在于 **Value（值）** 的内部数据组织形式。

---

#### 一、 5 大基础数据结构的 Key 与 Value 类型对照表

| 数据结构 | **Key 的类型** | **Value 的结构与元素类型** | 直观结构示意 |
| --- | --- | --- | --- |
| **`string`** | **String** | **单个 String**（可以是字符串、数字、JSON 或二进制数据） | `"user:1"` ➔ `"Alice"` |
| **`hash`** | **String** | **小字典（Field: String ➔ Value: String）** | `"user:1001"` ➔ `{ "name": "Alice", "age": "18" }` |
| **`list`** | **String** | **String 数组/链表**（每个元素都是 String） | `"tasks"` ➔ `[ "job1", "job2", "job3" ]` |
| **`set`** | **String** | **无序不重复 String 集合**（每个元素都是 String） | `"tags:1"` ➔ `{ "tech", "csharp", "vue" }` |
| **`zset`** | **String** | **(Member: String, Score: Double) 集合**（成员是 String，分数为双精度浮点数） | `"ranks"` ➔ `{ ("Alice", 95.5), ("Bob", 88.0) }` |

---

#### 二、 逐个拆解详述

##### 1. `string`（字符串）

* **Key**：`String`
* **Value**：`String`
* **特别说明**：虽然叫“字符串”，但因为 Redis 的字符串是**二进制安全**的，所以它不仅能存 `"hello"`，还能存数字 `"100"`（可以做 `INCR` 加一操作）、JSON 序列化字符串，甚至可以直接存图片/文件的二进制字节流（最大支持 512 MB）。

##### 2. `hash`（哈希）

* **Key**：`String`（大 Key）
* **Value**：一个内部的键值对映射表。
* 内部的键（称为 **Field**）：`String`
* 内部的值（称为 **Value**）：`String`

* **理解方式**：相当于两层 Key-Value 嵌套，即 `Map<String, Map<String, String>>`。

##### 3. `list`（列表）

* **Key**：`String`
* **Value**：一个有序的字符串链表（`List<String>`）。
* 列表里的**每一个节点元素**都是一个 `String`。

##### 4. `set`（集合）

* **Key**：`String`
* **Value**：一个无序且不可重复的字符串集合（`Set<String>`）。
* 集合里的**每一个成员**都是一个 `String`。

##### 5. `zset`（有序集合）

* **Key**：`String`
* **Value**：一个带有“权重分数”的有序元素集合。
* **成员（Member）**：`String`（必须唯一，不能重复）。
* **分数（Score）**：`Double`（双精度浮点数/数字，Redis 根据这个数字给成员排序）。

---

#### 总结

在 Redis 里，**一切数据的最底层元素本质上都是 String**（除了 ZSet 里的 Score 是浮点数字以外）。

如果你在 C# / ASP.NET Core 中使用 Redis 驱动（如 `StackExchange.Redis`），你会发现官方封装的类型叫 **`RedisKey`** 和 **`RedisValue`**，它们的底层本质也都是对 `string` 或 `byte[]` 的包装。

## Redis 操作技巧
### 为 Redis 的数据添加层次和结构
如果只用user当key，那么所有用户的数据都会挤在同一个空间里，当要存入下一个用户时就会产生冲突。

存入Key时，加上 `:1001` 、 `:1002` 使用冒号进行分隔时，数据就拥有了层级结构(冒号分隔可重复使用，如`:1001:alice`)，在图形化工具里如 `Redis Desktop Manager `里，会将这种层级结构以文件夹的形式呈现。
