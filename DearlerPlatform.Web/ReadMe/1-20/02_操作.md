### 修复Bug
上文中提到的 `GetListAsync` ，在传入委托查询时，`AsQueryable`处会报错，在此贴出报错原因:

💡 陌生概念：IAsyncEnumerable（异步可枚举接口）
传统的 IEnumerable 在循环时是同步的（一条一条连贯读完）。而在现代 .NET 中，为了支持异步流（比如从数据库网络连接中，随着网络的传输，异步地、源源不断地一条一条吐出数据），微软设计了 IAsyncEnumerable<T>。

EF Core 的 ToListAsync() 能够实现异步等待，底层死死依赖这个接口。  
为什么加上 .AsQueryable() 还是会报这个错？
回到上一轮提到的原因：  

因为你用了 Func<TEntity, bool>，dbSet.Where(predicate) 实际上调用的是内存 LINQ，它返回的是一个纯内存的 IEnumerable 迭代器对象。  

纯内存的迭代器对象绝对没有实现 IAsyncEnumerable 接口（因为内存数据不需要异步网络等待，直接就能读到）。  

紧接着你调用了 .AsQueryable()。这个方法其实是个“骗子”，它只是把一个内存的 IEnumerable 用一个外壳（EnumerableQuery）包装了一下，让编译器误以为它是个 IQueryable。  

最后你调用了 ToListAsync()。EF Core 的这个异步方法很聪明，它在后台会去剥开这个外壳，检查里面真实的底层数据源。结果它发现：“你这个底层的内存对象根本没有实现 IAsyncEnumerable，你根本没办法做真正的异步数据库读取！”

于是，它感到被欺骗了，直接愤怒地抛出了 InvalidOperationException。

#### 需要对GetListAsync进行改造
这里选择对 `DbSet` 和 `IAsyncEnumerable` ，添加相应的额外方法，来添加额外的对异步转换List的方案。
```
public static class LinqExtensions
{
    public async static IAsyncEnumerable<TEntity> WhereAsync<TEntity>(this DbSet<TEntity> dbSet, Func<TEntity, bool> predicate)
        where TEntity : class
    {
        var res = dbSet.Where(predicate);
        foreach (var item in res)
        {
            yield return item;
        }
    }

    public async static Task<List<TEntity>> ToListAsync<TEntity>(this IAsyncEnumerable<TEntity> listAsync)
    {
        List<TEntity> list = new();

        await foreach (var item in listAsync)
        {
            list.Add(item);
        }
        return list;

    }
}
```

#### 正式的写法：
直接将GetListAsync参数使用Expression表达式目录树包裹一层，表达式目录树里的Body属性可以将lambda表达式提取出来
```
public async Task<List<TEntity>> GetListAsync(Expression<Func<TEntity, bool>> predicate)
{
    var dbSet = _dbContext.Set<TEntity>();
    return await dbSet.Where(predicate).ToListAsync();
}
```
